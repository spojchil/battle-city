# 架构设计

## 概述

单人实时语音推理游戏。玩家在酒店大堂的平面图上自由走动，旁听 AI 角色之间的交谈，也可以直接开口与他们对话，在 20 分钟内收集录音和照片，阻止一起尚未发生的爆炸。

设计原则：

- **世界按真实时间 1:1 推进**：没有主持人或旁白，玩家不行动，世界也照常发展。
- **所有角色地位平等**：玩家只是其中一个角色。AI 角色与玩家使用同一套感知规则和行动规则。
- **声音有空间**：话语随路径距离和门衰减，离得远听不清，隔着门听不到。玩家与角色、角色与角色之间遵循同一规则。
- **通用引擎与剧本分离**：地图、角色、任务书、可交互点、提示和评判标准都写在剧本数据中，引擎不含具体剧情。

## 系统结构

```
浏览器（网页客户端）
  │  WebSocket /ws：状态、感知、字幕、角色语音 PCM ↓；移动、交互、拍照、麦克风 PCM ↑
  ▼
游戏服务（server/，单进程单端口）
  ├─ engine/      世界状态、地图寻路、声音传播、感知生成（唯一事实来源）
  ├─ runtime/     一局游戏的接线：角色思考循环、发声、语音识别、行动工具、评判
  ├─ /mcp         AI 角色的行动工具（灵矽云端 MCP）
  └─ /llm/v1      大模型网关（灵矽自定义模型）
        │                                 ▲
        ▼                                 │
灵矽平台（每个 AI 角色一个智能体、两台虚拟设备；玩家一台）
  ├─ brain 连接：感知文本 → 大模型（经网关） → 工具调用（经 MCP）
  ├─ mouth 连接：text_response 播报台词 → 逐句 PCM
  └─ ear 连接：玩家麦克风 PCM → 语音识别文本
        │
        ▼
上游大模型（默认 DeepSeek 官方 API deepseek-flash；可切换七牛 AI 大模型推理）
```

## 模块

### 引擎 `server/src/linx_game/engine/`

| 模块 | 职责 |
|---|---|
| `scenario.py` | 加载并校验剧本 YAML；报错信息带字段路径 |
| `grid.py` | 格子地图、四邻接寻路、受限门、声音路径（加权最短路：地板 1，门 4） |
| `sound.py` | 按音量（耳语、正常、大喊）与路径代价判定听清、听不清或听不到，并给出增益 |
| `world.py` | 世界状态与意图：移动、交互（可自动走近、可累计进度、周期声响）、说话（逐句、可中止）、拍照、录音、定时与条件提示 |
| `perception.py` | 把某个角色此刻的感知渲染为文本 |

**感知**在事件发生的那一刻，按当时的位置为每个角色计算并写入收件箱，包括：

- 听觉：清晰话语、模糊话语、声响、脚步声。
- 视觉：有人进入或离开视野。
- 结果：到达、交互结果、远程通知、提示。

AI 角色读到的感知文本，与玩家在网页上看到的录音笔内容同源。

### 运行时 `server/src/linx_game/runtime/`

| 模块 | 职责 |
|---|---|
| `session.py` | 灵矽设备长连接，后台接收并分发平台消息 |
| `brain.py` | 角色思考循环：有值得反应的感知时，等对方说完，再把感知文本作为一轮输入发给灵矽；一轮结束后再发下一轮。角色记忆（感知、内心想法、工具调用及结果）由这里保存 |
| `tools.py` | 行动工具（MCP）：`say`、`stop_speaking`、`move_to`、`interact`、`stop`、`wait`（可指定秒数，到时再思考）。工具只表达意图，由世界裁决并立即返回 |
| `voice.py` | mouth：用 `text_response` 播报台词，并逐句报告给世界；ear：转发玩家麦克风音频，取识别文本作为玩家说出的话 |
| `judge.py` | 结局评判：以值班警官的视角审阅录音与照片 |
| `game.py` | 一局游戏的生命周期：创建世界、连接设备、按玩家视野推送状态、按玩家位置为角色语音实时计算增益 |

### 大模型网关 `server/src/linx_game/llm_gateway.py`

灵矽把网关当作自定义模型调用，请求头 `x-linx-device-id` 标明是哪台设备。网关对 AI 角色的请求做以下处理：

- **重建上下文**：系统提示词（操控框架、角色背景、任务书、地点表）加一组示例和该角色的近期记忆。记忆由游戏保存，不依赖平台的对话历史。
- **截留正文**：模型正文是角色的内心想法，截留下来，不回传平台，因此不会被播报。
- **省掉二次调用**：工具结果返回后，平台会再请求一次模型，网关对这次请求直接返回空回复。
- **上游可切换**：默认 DeepSeek 官方 API，可通过 `LLM_UPSTREAM` 切换为七牛 AI 推理；限制同时进行的上游请求数，遇到 429 按退避重试。

### 网页客户端 `server/src/linx_game/web/static/`

纯前端，无构建步骤：

- **平面图**：Canvas 绘制。
- **操作**：键盘或点击移动、靠近交互、拍照、提交。
- **说话**：按住空格说话，由 AudioWorklet 采集 16 kHz PCM 上传。
- **角色语音**：按角色分别排队播放，音量按服务端给出的增益平滑调节。
- **侧栏**：字幕、录音笔、相册。

### 开发工具 `server/src/linx_game/devtools/`

- `provision.py`（`linx-provision`）：按剧本批量开通智能体与设备。每个 AI 角色一个智能体，音色取自剧本，并配 brain、mouth 两台设备；玩家一台 ear 设备。
- `vdevice.py`：灵矽虚拟设备，用于自动化测试。

## 一个 AI 角色的一轮行动

1. 世界产生值得反应的感知（例如有人对他说话），唤醒该角色。
2. 思考循环等对方说完这段话，渲染感知文本，经 brain 连接发给灵矽。
3. 灵矽调用网关；网关重建上下文后请求上游大模型，并截留模型正文（内心想法）。
4. 模型的工具调用经灵矽转到 `/mcp`，世界立即裁决。例如 `say` 开始一段台词，`move_to` 开始寻路。
5. 平台请求二次回复时，网关直接返回空回复，并通知思考循环本轮结束。
6. `say` 的台词交给 mouth 连接播报。每句开始播放时，世界按此刻的位置为附近角色生成听觉感知；音频按玩家位置的增益推送到浏览器。

## 关键设计决策

| 决策 | 依据（实测） |
|---|---|
| 行动全部走工具调用；提示词采用"你在操控一个角色"的框架，而非"你是某角色" | 用"你是某角色"的框架，0/4 次通过工具说话；改为操控框架后 4/4 |
| 说话与思考分离为两条连接（brain、mouth） | 同一连接上的新输入会自动中止正在播放的语音，无法边说边想 |
| 台词用 `text_response` 播报 | 跳过模型，首句约 0.5–2 秒；音色取该角色智能体的配置 |
| 正文写内心想法，由网关截留 | 不被播报，同时留作角色记忆与结局复盘材料 |
| 剧情节拍用提示（cues）逐步给出，形式为手机闹钟、来电等世界内的事 | 一开始给出完整的按钟点安排时，角色会抢在前提发生前行动 |
| 剧本文本只写客观事实，每个角色只掌握其真实可能知道的信息 | 交互结果中写了推论时，无关角色会直接说出线索的含义 |
| 角色记忆由游戏保存 | 平台对话历史中缺少工具调用，角色会重复自己说过的话 |
| 默认使用 DeepSeek 官方 API | 七牛免费模型每分钟请求数有限，6 个角色同时思考时约四分之一的请求被拒；deepseek-flash 单次约 1 秒，12 路并发无限流 |
| 智能体空闲超时设为 3600 秒 | 平台默认约 120 秒无语音活动即断开连接，角色的发声连接常常长时间空闲 |
| 不依据玩家语气设计玩法 | 实测灵矽对输入语气的感知接近随机 |

## 剧本格式

`scenarios/<id>/scenario.yaml` 包含以下内容：

- 地图：字符网格与图例。
- 房间：可标记为场外房间。
- 可交互点：状态描述、行动、完成效果。
- 角色：公开身份、私密背景、任务书、音色。
- 提示（cues）：按钟点或标志触发。
- 评判：真相与评判标准。

各字段的校验规则见 `engine/scenario.py`。

## 已知限制

- 角色从听到一句话到开口回应约 2–4 秒（等对方说完、模型推理、平台播报）。
- 浏览器麦克风需要 HTTPS 或 localhost。
- 角色是否听到一句话，以这句开始播放时的位置为准；玩家耳中的音量则按每个音频帧到达时双方的位置实时计算。
